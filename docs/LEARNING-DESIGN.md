# Leebs — Learning Design

## Philosophy

Leebs is designed around active understanding rather than passive
content consumption.

The application should encourage learners to:

- retrieve information
- explain reasoning
- notice misconceptions
- revise mental models
- apply concepts to new situations
- reflect on learning

## Learning Unit

The smallest learning unit is a micro-lesson.

A micro-lesson contains:

- learning objective
- explanation
- example
- optional visual
- quick check
- assessment
- reflection

Target duration:

5–10 minutes.

## Assessment Flow

### Correct answer

Correct
→ brief feedback
→ transfer/next question
→ mastery evidence

### Incorrect answer

Incorrect
→ ask for reasoning
→ learner explains
→ diagnose misconception
→ AI guidance
→ learner responds
→ transfer question
→ mastery evidence

## Reflection

Reflection should be lightweight.

Examples:

"Explain this idea in your own words."

"What was confusing at first?"

"What helped the concept make sense?"

"How would you explain this to a friend?"

Reflection should not feel like homework added after learning.

## Mastery

Mastery is concept-based.

States:

### Needs Practice

Learner has not yet demonstrated understanding.

### Developing

Learner shows partial understanding or requires significant guidance.

### Understanding

Learner successfully applies the concept after limited guidance.

### Strong

Learner demonstrates the concept correctly across repeated or
transfer questions.

MVP mastery logic can be deterministic.

Do not require AI to calculate mastery.

## Feedback

Good feedback should:

- acknowledge useful reasoning
- identify the gap
- avoid shame
- provide the smallest useful hint
- encourage another attempt

Avoid:

"Wrong."

Prefer:

"You're thinking about the right relationship, but there's one part
to reconsider."

## Product Principle

The learner should do meaningful cognitive work before the system
does it for them.
